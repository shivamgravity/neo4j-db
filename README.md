# Neo4J Graph Database Manager

This project demonstrates a Python application that interacts with a Neo4j Graph Database using the official `neo4j` Bolt driver. It programmatically manages a movie database schema, creating nodes (Persons, Movies) and relationships (ACTED_IN), and executing Cypher queries to retrieve data.

## Project Overview

The application performs the following operations against a local Neo4j instance:
1. **Connection:** Establishes a secure connection to the Neo4j DBMS.
2. **Data Creation:** Generates a knowledge graph connecting Actors (e.g., Keanu Reeves) to Movies (e.g., The Matrix, John Wick).
3. **Querying:** Executes parameterized Cypher queries to find and list movies associated with specific actors.
4. **Cleanup:** Includes utility functions to clear the database for testing purpose.

## Prerequisites

* **Python 3.8+**
* **Neo4j Desktop** (or a running Neo4j Sandbox/Aura instance)

## Setup & Installation
1. **Clone the Repository**
    ```bash
    git clone https://github.com/shivamgravity/neo4j-db
    cd neo4j-db
    ```
2. **Install Dependencies**
    This project requires the official Neo4j Python driver.
    ```bash
    pip install neo4j
    ```
3. **Configure Database Credentials**
    Open `app.py` and update the authentication data with your Neo4j username and password:
    ```python
    # Inside app.py
    URI = "neo4j://localhost:7687"
    AUTH = ("neo4j", "your_password_here")
    ```

## Usage

1. **Start your Neo4j Database** via Neo4j Desktop.
2. **Run the Application:**
    ```bash
    python app.py
    ```
3. **Expected Output:**
    The script will clear existing data, create the new graph, and print the query results:
    ```text
    Database cleared!
    Data created successfully!

    Movies starring Keanu Reeves:
    - The Matrix (1999)
    - John Wick (2014)
    ```

## Solution Architecture & Data Flow

This project implements a **Client-Server Architecture** designed to programmatically manage graph data.

### 1. System Components
* **Client Application (Python):** The core logic resides in `app.py`. It utilizes the **Neo4j Python Driver** to manage connection pooling and session creation.
* **Communication Layer (Bolt Protocol):** Data is transmitted between the Python client and the database using teh **Bolt protocol** over TCP port `7687`. This ensures high performance, binary communication compared to standard HTTP.
* **Data Storage (Neo4j DBMS):** The local Neo4j instance stores data in a **Property Graph Model**, optimizing for connected data queries (traversals) rather than table joins.

### 2. Data Model Schema
The application enforces a specific schema structure within the graph:
* **Nodes (Entities):**
    * `(:Person)`: Contains properties `name` (String) and `born` (Integer).
    * `(:Movie)`: Contains properties `title` (String) and `released` (Integer).
* **Relationships (Edges):**
    * `[:ACTED_IN]`: Connects a `Person` node to a `Movie` node. Includes the property `role` to specify the character played.

### 3. Execution Logic
The script follows a strict transactional flow to ensure data integrity:
1. **Initialization:** Establishes a driver instance using secure authentication.
2. **Session Management:** Opens a lightweight session for a sequence of transactions.
3. **Cypher Execution:** Sends parameterized Cypher queries to the database engine.
4. **Resource Cleanup:** Automatically closes the driver connection upon script completion to prevent memory leaks.
